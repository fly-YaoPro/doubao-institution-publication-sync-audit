# 匹配与考核口径

## 两类证据

1. 客户发布表：前一日真实发布的业务事实来源；包括原抖音、小红书客户发布表和新【独立端-内容发布】。新表由客户维护，审计只读。
2. 机构多维执行表：本 Skill 的考核目标；从统一 Base 动态发现当前 13 张机构表，并读取对应合作的实时“进度”。

抖音与小红书必须分开匹配。机构多维表按字段名读取 `唯一 ID、平台、达人名称、主页链接、脚本、发布时间、发布链接、进度`，不依赖视图、字段顺序或旧电子表格 Sheet ID。

独立端没有机构色块，匹配时先限定机构记录为`项目/专项=独立端+PC端`（兼容“双端”）且内容方向为独立端/豆包工作 APP，再按作品链接、稿件、主页、达人与日期消歧。PC 端仍按原工作任务处理，不能因为同属双端就把两期内容合并成一条。

## 判定

- `synced_exact`：客户发布能够唯一匹配机构合作，且机构表“进度=已发布”。
- `missing / 进度未更新`：唯一匹配到机构合作，但进度为空或不是“已发布”，计入机构未及时更新。
- `missing / 机构记录缺失`：13 张机构表完全找不到对应合作，计入机构未及时更新；机构归属无法确认时标记“待确认机构”。
- `ambiguous`：同名多期合作、多机构同名或多条同分候选无法消歧，进入人工核对，不猜测归属。

## 及时率

`次日上午进度更新及时率 = 10:00 时进度已为“已发布”的数量 ÷ 前一日该机构客户表真实发布数`

- 分母为 0 时结果为 `N/A`，不参与机构排名。
- 10:00 后更新进度可在后续复查中转为已同步，同时保留首次检查的未更新事实与实际更新时间。
- 长期考核至少保留：业务日期、检查时间、机构、平台、应更新数、准时更新数、迟到更新数、未更新数、待核数、及时率、来源 revision、证据链接。

## 防误配

- 优先按作品、主页和稿件等强证据锁定合作；不能只靠达人昵称。
- 同一达人可由不同机构在不同时间合作。
- 短链与完整作品链接不能直接比字符串，必须解析到最终作品 ID。
- 不得用 CSV 展示文本或单元格外观直接判冲突。遇到标题链接、纯文本链接、富文本链接或错误显示格式混用时，先读取真实超链接目标并规范化；只有真实目标仍冲突或存在多条候选时才进入待核。
- 抖音发布入口可能表现为 `/user/...`，但在 `group_id`、`from_gid`、`vid` 中携带作品 ID；这些参数一致时，应与 `/video/<id>` 视为同一作品证据。
- 昵称中的数字默认属于账号名，不得擅自删除；只有存在明确业务证据时才能清理人为追加的期数标记。
- 同达人多期合作必须逐期匹配；课程教学批量十期不是重复数据。
- 没有可验证证据时宁可标待核，不得猜测已同步或机构归属。
